Asymptotic Analysis

BIG-O · BIG-Ω · BIG-Θ · LITTLE-o · RECURRENCES · MASTER THEOREM

Formal Definitions

Used to represent the time and space complexity of an algorithm as input size n → ∞.

  • O(g(n)) [Big-O, Upper Bound]: f(n) = O(g(n)) if ∃ c > 0, n₀ > 0 such that 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀.
  • Ω(g(n)) [Big-Omega, Lower Bound]: f(n) = Ω(g(n)) if ∃ c > 0, n₀ > 0 such that 0 ≤ c·g(n) ≤ f(n) for all n ≥ n₀.
  • Θ(g(n)) [Big-Theta, Tight Bound]: f(n) = Θ(g(n)) if f(n) = O(g(n)) and f(n) = Ω(g(n)). ∃ c₁, c₂ > 0, n₀ > 0 such that 0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀.
  • o(g(n)) [Little-o, Strict Upper Bound]: f(n) = o(g(n)) if ∀ c > 0, ∃ n₀ > 0 such that 0 ≤ f(n) < c·g(n) for all n ≥ n₀. Equivalently, lim(n→∞) f(n)/g(n) = 0.
  • ω(g(n)) [Little-omega, Strict Lower Bound]: f(n) = ω(g(n)) if ∀ c > 0, ∃ n₀ > 0 such that 0 ≤ c·g(n) < f(n) for all n ≥ n₀. Equivalently, lim(n→∞) f(n)/g(n) = ∞.

Common Growth Rates

In increasing order of complexity:

O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)

Properties

  • Transitivity: If f(n) = O(g(n)) and g(n) = O(h(n)), then f(n) = O(h(n)). Holds for Ω and Θ as well.
  • Sum Rule: O(f(n)) + O(g(n)) = O(max(f(n), g(n))). Drop lower-order terms.
  • Product Rule: O(f(n)) · O(g(n)) = O(f(n) · g(n)).

Recurrence Relations & Master Theorem

The Master Theorem solves recurrences of the form:

T(n) = aT(n/b) + f(n) where a ≥ 1, b > 1

Compare f(n) with n^(log_b(a)):

  • Case 1: f(n) = O(n^(log_b(a) - ε)) for ε > 0. → T(n) = Θ(n^(log_b(a)))
  • Case 2: f(n) = Θ(n^(log_b(a))). → T(n) = Θ(n^(log_b(a)) · log n)
  • Case 3: f(n) = Ω(n^(log_b(a) + ε)) for ε > 0, and a·f(n/b) ≤ c·f(n) for c < 1. → T(n) = Θ(f(n))

Substitution Method: Useful for T(n) = T(n-1) + 1 style recurrences (subtract and conquer).

Common Recurrences

RecurrenceSolutionAlgorithm Example
T(n) = 2T(n/2) + nΘ(n log n)Merge Sort
T(n) = 2T(n/2) + 1Θ(n)Tree Traversal
T(n) = T(n/2) + 1Θ(log n)Binary Search
T(n) = T(n-1) + nΘ(n²)Bubble/Insertion Sort
T(n) = T(n-1) + 1Θ(n)Linear Search (Recursive)
GATE trap

1. Confusing O (upper bound) with Θ (tight bound). For example, insertion sort is O(n²) and O(n³) is technically true, but Θ(n²) is the tight worst-case bound.
2. Master theorem doesn't apply to all recurrences (e.g., T(n) = 2T(n/2) + n/log n, which falls in the gap between cases 1 and 2).

Practice — GATE style (original)

5 questions
Q1 Find the tight bound for T(n) = 3T(n/2) + n².

Here, a=3, b=2, f(n)=n². Compare f(n) with n^(log₂3) ≈ n^1.58. Since f(n) = Ω(n^(log₂3 + ε)) (Case 3), and 3(n/2)² = (3/4)n² ≤ cn² for c=3/4 < 1, the result is T(n) = Θ(f(n)).

Answer: Θ(n²)

Q2 Solve T(n) = 2T(n/2) + n log n.

This is an extension of Master Theorem Case 2. Since f(n) = Θ(n^(log₂2) · log n) = Θ(n log n), the solution is T(n) = Θ(n log² n).

Answer: Θ(n log² n)

Q3 True or False: 2^(n+1) = O(2ⁿ).

2^(n+1) = 2 · 2ⁿ. Since 2 · 2ⁿ ≤ c · 2ⁿ for c = 2, this statement is true.

Answer: True

Q4 True or False: 2^(2n) = O(2ⁿ).

2^(2n) = 4ⁿ. For 4ⁿ ≤ c · 2ⁿ, we need (4/2)ⁿ = 2ⁿ ≤ c, which is impossible for a constant c as n → ∞.

Answer: False

Q5 Consider T(n) = T(√n) + 1. Find the complexity.

Substitute n = 2^m, so m = log n. T(2^m) = T(2^(m/2)) + 1. Let S(m) = T(2^m). Then S(m) = S(m/2) + 1. By Master Theorem, S(m) = Θ(log m). Substituting back, T(n) = Θ(log log n).

Answer: Θ(log log n)

02

Searching

LINEAR SEARCH · BINARY SEARCH · TERNARY SEARCH · LOWER BOUNDS

Linear Search

Checks elements one by one. Works on unsorted arrays.

  • Best Case: O(1) (element found at index 0)
  • Worst/Average Case: O(n)

Binary Search

Requires a sorted array. Divides the search space in half each step.

mid = low + (high - low)/2

Using mid = (low + high)/2 can cause integer overflow in languages like C/C++/Java for large arrays. The formula above avoids this.

  • Best Case: O(1) (element is at mid)
  • Worst/Average Case: O(log n)

Variants: Finding the first or last occurrence of a duplicated element, finding the lower bound (first element ≥ x) or upper bound (first element > x).

Ternary Search

Divides the search space into three parts. Works on unimodal functions or sorted arrays. Complexity is O(log₃ n), which is asymptotically O(log n), but practically slower than binary search due to more comparisons per step.

Lower Bound for Comparison-based Search

A decision tree for searching an element in an array of size n has at least n+1 leaves (n successful outcomes + 1 unsuccessful). A binary tree with L leaves has height h ≥ ⌈log₂ L⌉. Thus, h ≥ log₂(n+1) = Ω(log n). Binary search achieves this lower bound and is optimal.

GATE trap

Off-by-one errors in binary search bounds: using while (low < high) vs while (low <= high), or updating low = mid instead of low = mid + 1 causing infinite loops. Binary search on answer technique is often tested in algorithmic questions (e.g., finding the minimum capacity of a ship to transport goods within D days).

Practice — GATE style (original)

5 questions
Q1 How many comparisons are required in the worst case to find an element in a sorted array of 1024 elements using binary search?

Worst-case comparisons = ⌈log₂(n+1)⌉ = ⌈log₂(1025)⌉ = 11. Or simply checking bounds: 1024 → 512 → 256 → 128 → 64 → 32 → 16 → 8 → 4 → 2 → 1 → 0.

Answer: 11

Q2 Given an array A of n distinct elements, we want to find both the minimum and maximum elements. What is the minimum number of comparisons needed?

Using tournament method (comparing pairs): ⌈3n/2 - 2⌉ comparisons. This is a standard well-known result for min-max finding.

Answer: ⌈3n/2 - 2⌉

Q3 What is the time complexity of searching in a sorted linked list?

Even though the list is sorted, random access is not possible. You cannot find the middle element in O(1) time. Thus, binary search takes O(n) time, equivalent to linear search.

Answer: O(n)

Q4 Binary search is performed on the sorted array: [2, 4, 6, 8, 10, 12, 14, 16]. If the target is 6, what is the sequence of mid elements examined? (assume mid = floor((low+high)/2) and 0-based indexing)

low=0, high=7. mid=3 (val 8). 6 < 8, so high=2. low=0, high=2. mid=1 (val 4). 6 > 4, so low=2. low=2, high=2. mid=2 (val 6). Found.

Answer: 8, 4, 6

Q5 An array contains n elements. A linear search is performed to find an element. If the element has a uniform probability of being anywhere in the array, what is the average number of comparisons?

The element can be at index 1, 2, ..., n. Average = (1 + 2 + ... + n) / n = [n(n+1)/2] / n = (n+1)/2.

Answer: (n+1)/2

03

Sorting

COMPARISON SORTS · NON-COMPARISON SORTS · STABILITY · LOWER BOUND Ω(n log n)

Comparison-Based Sorts

  • Bubble Sort: Repeatedly swaps adjacent elements. O(n²) worst/avg. Can be optimized to O(n) best case (with a swapped flag). Stable. In-place.
  • Selection Sort: Finds the minimum and swaps it to the front. O(n²) in all cases. Not stable (e.g., [4a, 4b, 2] → [2, 4b, 4a]). In-place.
  • Insertion Sort: Builds the sorted array one element at a time. O(n²) worst/avg. O(n) best case (when nearly sorted). Stable. In-place. Excellent for small n.
  • Merge Sort: Divide & conquer. Divides array in half, recursively sorts, and merges. Θ(n log n) in all cases. Stable. NOT in-place (requires O(n) extra space).
  • Quick Sort: Divide & conquer. Picks a pivot, partitions array around it. O(n log n) average. O(n²) worst case (when array is already sorted and bad pivot like first/last element is chosen). Randomized quicksort fixes this to expected O(n log n). Not stable. In-place.
  • Heap Sort: Builds a max-heap, repeatedly extracts max. Θ(n log n) all cases. Not stable. In-place.

Non-Comparison Sorts

  • Counting Sort: O(n + k) time and space, where k is the range of inputs. Works well when k = O(n). Stable.
  • Radix Sort: O(d(n + k)) time, where d is the number of digits. Sorts digit by digit using a stable sort (like Counting Sort).
  • Bucket Sort: O(n) average time. Distributes elements into buckets, then sorts buckets. Useful for uniformly distributed floats in [0, 1).
Lower Bound Proof Sketch: Ω(n log n)

A sorting algorithm based on comparisons can be modeled as a decision tree. For n elements, there are n! possible permutations (leaves of the tree). A binary tree of height h has at most 2^h leaves. Thus, 2^h ≥ n! ⇒ h ≥ log₂(n!). Using Stirling's approximation, log₂(n!) = Θ(n log n). Hence, the worst-case number of comparisons is Ω(n log n).

GATE trap

1. Quicksort's worst-case time is O(n²), not O(n log n) — it happens when the partition is always highly unbalanced (e.g., sorted array with first/last element pivot).
2. Merge sort requires O(n) extra space, making it unfavorable for large in-memory arrays compared to Quicksort.
3. Stability matters when sorting multi-key records (e.g., sort by name, then by age). Stable sorts preserve the relative order of equal keys.

Practice — GATE style (original)

5 questions
Q1 Which sorting algorithm is optimal for an array that is almost sorted (few inversions)?

Insertion sort runs in O(n + I) time where I is the number of inversions. For an almost sorted array, I is very small, making insertion sort run in O(n) time.

Answer: Insertion Sort

Q2 You need to sort a very large dataset that cannot fit into RAM. Which sorting algorithm is best?

External Merge Sort is used for data that is too large to fit in memory (external memory). It sorts chunks in RAM, writes them to disk, and then merges them.

Answer: Merge Sort

Q3 What is the worst-case time complexity of Quick Sort, and what input causes it (assuming the pivot is the first element)?

Worst-case is O(n²). It occurs when the array is already sorted (ascending or descending), leading to partitions of size 0 and n-1 at every step.

Answer: O(n²) for an already sorted array

Q4 A sorting algorithm is stable if...

It maintains the relative order of records with equal keys. If A appears before B in the input and A = B in value, A will appear before B in the sorted output.

Answer: Relative order of equal elements is preserved

Q5 How many comparisons does Selection Sort make on an array of size n?

Selection sort always makes (n-1) + (n-2) + ... + 1 = n(n-1)/2 comparisons, regardless of the initial order of elements.

Answer: n(n-1)/2 (which is Θ(n²))

Hashing

HASH FUNCTIONS · COLLISION HANDLING · CHAINING · OPEN ADDRESSING · LOAD FACTOR

Hash Functions

A hash function maps a key to an index in the range [0, m−1]. The ideal hash function provides a uniform distribution of keys across all slots.

  • Division method: h(k) = k mod m (choose m as prime, not power of 2)
  • Multiplication method: h(k) = ⌊m(kA mod 1)⌋ where 0 < A < 1

Collision Handling

  • Separate chaining: each slot is a linked list, search/insert/delete O(1+α) average where α = n/m (load factor)
  • Open addressing: probe sequence within table
    • Linear probing: h(k,i) = (h(k) + i) mod m — suffers from primary clustering
    • Quadratic probing: h(k,i) = (h(k) + c₁i + c₂i²) mod m — secondary clustering
    • Double hashing: h(k,i) = (h₁(k) + i·h₂(k)) mod m — best distribution
Load factor (α)
α = n / m

For chaining α can exceed 1; for open addressing α < 1 (table must have empty slots).

Expected probes
Chaining successful = 1 + α/2 Open addressing successful ≈ (1/α)ln(1/(1−α))

Comparison table

FeatureChainingOpen addressing
SpaceExtra space for pointersNo extra pointers
ClusteringNo clusteringPrimary/secondary clustering
DeletionEasy (linked list removal)Requires tombstones
Load factor (α)Can exceed 1Must be < 1
GATE trap

Linear probing clustering; deletion in open addressing requires tombstones; choosing m as power of 2 with division method.

Practice — GATE style (original)

5 questions
Q1 Given a hash table of size 10 and hash function h(k) = k mod 10, insert 15, 25, 35 using linear probing. How many probes are required for 35?

Insert 15: h(15)=5 (1 probe). Insert 25: h(25)=5 (collision), probe to 6 (2 probes). Insert 35: h(35)=5 (collision), probe to 6 (collision), probe to 7 (3 probes).

Answer: 3 probes

Q2 In a hash table using chaining, the load factor is α. What is the expected time for an unsuccessful search?

In chaining, an unsuccessful search must traverse the entire linked list at the hashed slot. The average length of this list is exactly α. Computing the hash function takes O(1) time.

Answer: O(1 + α)

Q3 Which collision resolution technique is most prone to primary clustering?

Linear probing sequentially checks slots, causing contiguous blocks of occupied slots to merge, which is known as primary clustering. Quadratic probing causes secondary clustering. Double hashing avoids both.

Answer: Linear probing

Q4 A hash table of size m=11 uses double hashing with h₁(k) = k mod 11 and h₂(k) = 1 + (k mod 10). Insert key 33. What is the probe sequence?

h₁(33) = 33 mod 11 = 0. If slot 0 is full, we use h₂(33) = 1 + (33 mod 10) = 1 + 3 = 4. The probe sequence is (h₁(k) + i·h₂(k)) mod 11. For i=0, index is 0. For i=1, index is (0 + 1·4) = 4. For i=2, index is (0 + 2·4) mod 11 = 8.

Answer: 0, 4, 8, 1, 5, ...

Q5 Can the load factor α be greater than 1 in open addressing?

No. In open addressing, every element is stored directly in the hash table array. Thus, the number of elements (n) cannot exceed the number of slots (m). Therefore, α = n/m must be ≤ 1.

Answer: No, α must be ≤ 1

Divide & Conquer

DIVIDE · CONQUER · COMBINE · RECURRENCES · CLASSIC ALGORITHMS

The D&C Paradigm

Split problem into subproblems, solve recursively, combine solutions. Works well for problems with optimal substructure that decompose cleanly into independent subproblems.

Classic D&C algorithms

AlgorithmRecurrence RelationTime Complexity
Binary searchT(n) = T(n/2) + O(1)O(log n)
Merge sortT(n) = 2T(n/2) + O(n)O(n log n)
Quick sort (best/avg)T(n) = 2T(n/2) + O(n)O(n log n)
Quick sort (worst)T(n) = T(n−1) + O(n)O(n²)
Strassen's matrix mult.T(n) = 7T(n/2) + O(n²)O(n^2.81) vs naive O(n³)
Max subarrayT(n) = 2T(n/2) + O(n)O(n log n)
Closest pair of pointsT(n) = 2T(n/2) + O(n log n)O(n log n)
Master Theorem quick reference

For recurrences of the form T(n) = aT(n/b) + O(nᵏ logᵖ n), compare a with bᵏ:

If a > bᵏ ⟹ T(n) = O(n^(log_b a)) If a = bᵏ ⟹ T(n) = O(nᵏ log^(p+1) n) (if p ≥ 0) If a < bᵏ ⟹ T(n) = O(nᵏ logᵖ n)
Comparison: D&C vs DP

D&C has independent subproblems, whereas DP has overlapping subproblems. Both rely on optimal substructure.

GATE trap

Quicksort worst case happens when array is already sorted and we pick the first/last element as pivot. Strassen's constant is large, which means naive matrix multiplication is faster for small n (the crossover point).

Practice — GATE style (original)

5 questions
Q1 Solve the recurrence T(n) = 2T(n/2) + n log n.

Here a=2, b=2, f(n) = n log n. Since log_b(a) = log_2(2) = 1, we compare f(n) with n¹. It matches the extended Master Theorem form nᵏ logᵖ n with k=1, p=1. Since a = bᵏ (2 = 2¹), T(n) = Θ(nᵏ log^(p+1) n).

Answer: Θ(n log² n)

Q2 In which scenario does Quick Sort exhibit its worst-case time complexity?

The worst-case occurs when the partitioning routine always selects the smallest or largest element as the pivot, reducing the problem size by only 1. This happens when the array is already sorted and we pick the first/last element as pivot.

Answer: When the array is already sorted (and first/last element is the pivot)

Q3 What is the time complexity of Strassen's Matrix Multiplication and what recurrence generates it?

Strassen reduces 8 multiplications of (n/2)×(n/2) matrices to 7. The recurrence is T(n) = 7T(n/2) + O(n²). By Master Theorem, log_2(7) ≈ 2.81.

Answer: O(n^2.81) from T(n) = 7T(n/2) + O(n²)

Q4 True or False: Dynamic Programming is always strictly better than Divide and Conquer.

False. DP uses extra memory for memoization/tabulation. If subproblems do not overlap (like in Merge Sort), DP provides no benefit and D&C is the correct, more efficient paradigm.

Answer: False

Q5 What is the time complexity of the combine step in the D&C approach to the Maximum Subarray problem?

The combine step must find the maximum subarray that crosses the midpoint. This requires a linear scan from the midpoint to the left and right.

Answer: O(n)

Greedy Algorithms

GREEDY CHOICE · OPTIMAL SUBSTRUCTURE · CLASSIC PROBLEMS · GREEDY vs DP

Greedy Paradigm

Make locally optimal choice at each step, hoping for global optimum. Two properties needed:

  • Greedy choice property
  • Optimal substructure

Classic greedy algorithms

  • Activity/Job selection: sort by finish time, select non-overlapping — O(n log n)
  • Fractional knapsack: sort by value/weight ratio, fill greedily — O(n log n). NOTE: 0/1 knapsack is NOT greedy (it's DP)
  • Huffman coding: build optimal prefix-free code tree using min-heap — O(n log n)
    • How it works: repeatedly merge two lowest-frequency nodes
    • Properties: no codeword is a prefix of another; optimal for variable-length encoding
  • Job sequencing with deadlines: sort by profit, assign latest available slot
  • Minimum number of platforms/intervals problem: track arrivals/departures, sort all times, and count max overlaps
When greedy fails

0/1 knapsack, shortest path with negative weights (Dijkstra fails), coin change (for arbitrary denominations).

Comparison table: Greedy vs DP

FeatureGreedyDynamic Programming
ApproachTop-down (make choice, then solve subproblem)Bottom-up (solve subproblems, then make choice)
SubproblemsOnly solves one subproblemSolves all overlapping subproblems
Optimality guaranteeMust be proven (doesn't always guarantee)Always guarantees optimal solution if optimal substructure holds
GATE trap

Fractional knapsack is greedy but 0/1 knapsack is DP — GATE loves testing this. Greedy doesn't always give optimal solution.

Practice — GATE style (original)

5 questions
Q1 For the Activity Selection problem, what is the optimal sorting criteria to guarantee a greedy choice works?

Activities must be sorted in ascending order of their finish times to leave the maximum possible free time for remaining activities.

Answer: Sort by finish time

Q2 Given items with (Value, Weight): A(60, 10), B(100, 20), C(120, 30). Knapsack capacity is 50. Find max value using Fractional Knapsack.

Ratios (V/W): A=6, B=5, C=4. Sort by ratio: A, B, C. Take A (W=10, V=60), Take B (W=20, V=100). Remaining capacity = 50 - 30 = 20. Take fraction of C: (20/30) * 120 = 80. Total value = 60 + 100 + 80 = 240.

Answer: 240

Q3 Which of the following problems cannot be solved optimally using a Greedy approach? (A) Huffman Coding (B) Fractional Knapsack (C) 0/1 Knapsack (D) Job Sequencing with Deadlines

0/1 Knapsack requires considering all combinations to maximize value without exceeding weight (overlapping subproblems), which requires Dynamic Programming. The rest have greedy choice properties.

Answer: (C) 0/1 Knapsack

Q4 In Huffman coding, if the characters a, b, c, d have frequencies 1, 2, 3, 4 respectively, what is the cost of the optimal tree (sum of weighted path lengths)?

Merge min two: {a:1, b:2} → node(3). Remaining: {node(3), c:3, d:4}. Merge min two: {node(3), c:3} → node(6). Remaining: {node(6), d:4}. Merge: {node(10)}. Tree cost = sum of internal node values = 3 + 6 + 10 = 19.

Answer: 19

Q5 Dijkstra's algorithm is a greedy algorithm. Under what condition does it fail to find the optimal shortest path?

Dijkstra's assumes that once a node's shortest path is finalized, it will never be improved. This assumption breaks when the graph contains edges with negative weights, as a later, longer path could have a massive negative edge that reduces the total cost.

Answer: When the graph has negative edge weights

Dynamic Programming

OPTIMAL SUBSTRUCTURE · OVERLAPPING SUBPROBLEMS · MEMOIZATION · TABULATION

Dynamic Programming Paradigm

DP solves problems by combining the solutions to overlapping subproblems. It stores the results of subproblems (memoization or tabulation) to avoid redundant recomputation, bringing exponential time complexities down to polynomial.

Two key properties required for DP:

  • Optimal Substructure: An optimal solution to the problem contains optimal solutions to its subproblems.
  • Overlapping Subproblems: The space of subproblems is small; the recursive algorithm visits the same subproblems repeatedly.

Top-down (Memoization) vs Bottom-up (Tabulation): Both generally have the same asymptotic time complexity. Top-down is easier to write (recursion + cache) and only computes needed states. Bottom-up has no recursion overhead and is often easier to space-optimize.

Classic DP Problems

0/1 Knapsack: Items cannot be split. DP[i][w] is the maximum value using first i items and weight limit w.

DP[i][w] = max(DP[i-1][w], val[i] + DP[i-1][w-wt[i]])

Time: O(nW), Space: O(nW). Space optimization: 1D array O(W) when only the previous row is needed.

Longest Common Subsequence (LCS): Length of the longest subsequence common to both strings X and Y.

DP[i][j] = DP[i-1][j-1] + 1 if X[i] = Y[j] DP[i][j] = max(DP[i-1][j], DP[i][j-1]) if X[i] ≠ Y[j]

Time: O(mn), Space: O(mn) (can be optimized to O(min(m,n))).

Longest Increasing Subsequence (LIS): Naive DP takes O(n²), optimizing to O(n log n) with patience sorting/binary search.

Matrix Chain Multiplication (MCM): Minimum scalar multiplications to compute product of n matrices. Dimensions p[0]...p[n].

DP[i][j] = min_{i≤k

Time: O(n³), Space: O(n²).

Edit Distance: Minimum operations (insert, delete, replace) to convert string X to Y.

DP[i][j] = min(insert, delete, replace) DP[i][j] = min(DP[i][j-1]+1, DP[i-1][j]+1, DP[i-1][j-1] + cost)

Time: O(mn), Space: O(mn).

DP vs Naive Recursion

Example: Fibonacci numbers. Naive recursion F(n) = F(n-1) + F(n-2) takes exponential time O(2ⁿ). DP (memoization or tabulation) stores previously computed values, reducing time to linear O(n) and making it practically computable.

GATE trap

DP ≠ Recursion. A problem must have overlapping subproblems to benefit from DP (e.g., Divide & Conquer problems like merge sort have independent subproblems, so DP doesn't apply). Also, 0/1 Knapsack time is pseudo-polynomial O(nW), not strictly polynomial. Always check if a greedy approach works first (it's simpler and takes less space).

Practice — GATE style (original)

5 questions
Q1 To compute the LCS of two strings of lengths m and n, what is the maximum number of distinct subproblems solved?

The DP table size is m × n, meaning there are mn distinct subproblems to solve, each taking O(1) time. The total number of distinct subproblems is strictly bounded by m·n.

Answer: m × n

Q2 Can the 0/1 Knapsack DP table be space-optimized to a 1D array?

Yes. The recurrence DP[i][w] only depends on the previous row (i-1). By updating a 1D array backwards (from capacity W down to 0), space complexity reduces from O(nW) to O(W).

Answer: Yes, space can be reduced to O(W)

Q3 Is the O(nW) time complexity of the 0/1 Knapsack problem considered polynomial?

No, it is pseudo-polynomial. The number of bits needed to represent the capacity W is log₂W. Therefore, W is exponential with respect to its input size (log₂W), making O(nW) an exponential time algorithm in the worst case.

Answer: No, it is pseudo-polynomial

Q4 Which classic DP problem uses a recurrence relation that checks all possible splitting points k between i and j?

Matrix Chain Multiplication (MCM) iterates through every possible split point k (where i ≤ k < j) to find the minimum cost to multiply matrices from index i to j.

Answer: Matrix Chain Multiplication

Q5 How can we identify whether a problem should be solved with DP instead of Greedy?

DP is used when a problem has optimal substructure AND overlapping subproblems, but the greedy choice property cannot be proven (i.e., local optimal choices do not guarantee a global optimum, like in 0/1 Knapsack).

Answer: When greedy fails to guarantee a global optimum despite having optimal substructure

Graph Algorithms

BFS/DFS · TOPOLOGICAL SORT · MST · SHORTEST PATHS · COMPLEXITY

Traversals and Topological Sort

BFS (Queue): Shortest path in unweighted graphs. DFS (Stack/Recursion): Cycle detection, connectivity, and topological sorting. Both take O(V+E) time using an adjacency list.

Topological Sort: A linear ordering of vertices in a Directed Acyclic Graph (DAG) such that for every directed edge u→v, u comes before v. Used in task scheduling and prerequisite ordering.

  • DFS approach: Reverse post-order traversal (push to stack upon finishing a vertex).
  • BFS approach (Kahn's Algorithm): Iteratively remove vertices with in-degree 0.

Minimum Spanning Tree (MST)

MST properties: Cut Property (min weight edge crossing any cut belongs to MST) and Cycle Property (max weight edge in any cycle does not belong to MST). The MST is unique if all edge weights are distinct.

Dijkstra & Bellman-Ford

Dijkstra uses a greedy min-heap approach. Bellman-Ford relaxes all edges V−1 times. If a V-th relaxation succeeds, it detects a negative weight cycle.

Floyd-Warshall

Uses DP on intermediate vertices: dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j]). Handles negative weights, but not negative cycles.

Complexity summary
BFS / DFS: O(V+E) Kruskal: O(E log E) Prim (Heap): O(E log V) Dijkstra (Heap): O((V+E) log V) Bellman-Ford: O(VE) Floyd-Warshall: O(V³)
GATE trap

Adding a constant positive weight to all edges of a graph does not preserve the shortest paths (a path with more edges gets penalized more heavily). However, adding a constant weight to all edges does preserve the Minimum Spanning Tree. Dijkstra fundamentally fails with negative edges—GATE loves giving a graph with one negative edge to trick you into tracing Dijkstra's.

Practice — GATE style (original)

5 questions
Q1 Which data structure is essential for efficiently implementing Kruskal's algorithm?

Kruskal's algorithm needs to rapidly check if adding an edge forms a cycle. A Disjoint Set (Union-Find) data structure does this efficiently in nearly O(1) time.

Answer: Union-Find (Disjoint Set)

Q2 In Bellman-Ford, how many passes of edge relaxation are required to detect a negative weight cycle?

The shortest path can have at most V−1 edges. The algorithm normally does V−1 passes. A V-th pass is done strictly to detect negative cycles (if any distance updates, a cycle exists).

Answer: V passes in total

Q3 True or False: Topological sorting can be performed on any directed graph.

False. Topological sort is only defined for Directed Acyclic Graphs (DAGs). If a graph contains a cycle, no valid linear ordering is possible.

Answer: False (only for DAGs)

Q4 If all edge weights in a graph are distinct, how many Minimum Spanning Trees can it have?

A standard property of MSTs is that if all edge weights are distinct, the MST is absolutely unique.

Answer: Exactly one

Q5 Why does Dijkstra's algorithm fail on graphs with negative edge weights?

Dijkstra's is a greedy algorithm. Once a vertex is extracted from the min-heap, its shortest path is considered "finalized". A negative edge could offer a cheaper path to a finalized vertex later, which Dijkstra's ignores.

Answer: It assumes extracted vertices are strictly finalized

Asymptotic Notations

O(g): Upper bound. Ω(g): Lower bound. Θ(g): Tight bound. Master theorem: compare f(n) with n^(log_b(a)) across 3 cases.

Searching & Lower Bounds

Binary Search: O(log n). Lower bound for comparison-based sorting: Ω(n log n). Lower bound to search an unsorted array: Ω(n).

Sorting Algorithm Limits

Merge: Θ(n log n) stable, out-of-place. Quick: worst O(n²), avg O(n log n), in-place. Heap: O(n log n) in-place, unstable.

Hashing Basics

Load factor α = n/m. Chaining expected search: O(1 + α). Open addressing expected probes for unsuccessful search: 1/(1−α).

Divide & Conquer

Recurrence patterns. Merge sort: T(n) = 2T(n/2) + O(n). Binary search: T(n) = T(n/2) + O(1). Strassen's Matrix Mult: O(n^2.81).

Greedy Algorithms

Activity Selection (sort finish time), Huffman Coding (min heap), Fractional Knapsack (sort val/wt). All operate in O(n log n).

Dynamic Programming

0/1 Knapsack O(nW), LCS O(mn), LIS O(n log n), MCM O(n³). DP requires optimal substructure AND overlapping subproblems.

Graph: Spanning Trees

Kruskal (sort edges + Union-Find) O(E log E). Prim (Heap) O(E log V). Adding constant weight to all edges preserves the MST.

Graph: Shortest Paths

Dijkstra O((V+E)log V), fails on negative edges. Bellman-Ford O(VE), detects negative cycles. Floyd-Warshall O(V³), all-pairs DP.

Key Distinctions

Greedy vs DP: Greedy has no look-ahead. D&C vs DP: D&C has independent subproblems, DP has overlapping subproblems.

Practice — rapid-fire mix (original)

5 questions
Q1 What is the worst-case time complexity of Quick Sort?

When the pivot is consistently the smallest or largest element (e.g., already sorted array), the recurrence is T(n) = T(n−1) + O(n).

Answer: O(n²)

Q2 True or False: Adding a constant weight to all edges in a graph preserves the shortest paths.

False. Paths with more edges will accumulate more of the added weight, potentially changing which path is considered the shortest overall.

Answer: False

Q3 What is the maximum number of edges in an n-node acyclic undirected graph?

An acyclic undirected graph is a tree (if connected) or a forest. A tree with n nodes has exactly n−1 edges.

Answer: n − 1

Q4 Does Dijkstra's algorithm work for graphs with cycles?

Yes, Dijkstra's algorithm handles cycles perfectly well, provided that there are no negative weight edges in the graph.

Answer: Yes, as long as there are no negative weights

Q5 Which data structure is optimal for implementing Huffman coding?

Huffman coding repeatedly extracts the two minimum frequency nodes to combine them. A Min-Heap performs these extractions in O(log n) time.

Answer: Min-Heap
