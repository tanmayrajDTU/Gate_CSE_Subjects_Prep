01

Basic Organization & Register Transfer

FUNCTIONAL UNITS · VON NEUMANN vs HARVARD · BUSES · RTL

The functional units of a computer

Every computer, however it is built, is organized around five interacting functional units: the input unit, memory, the arithmetic-logic unit (ALU), the output unit, and the control unit. The ALU and control unit together are usually referred to as the CPU, and the CPU plus memory plus I/O form the complete system, all tied together by a shared communication path called the bus.

CPU-centric view

The CPU itself is built from three cooperating pieces: a register file (fast on-chip storage for operands and results), the ALU (does the actual arithmetic/logic), and the control unit (generates the timing and control signals that make the other two do the right thing at the right moment, driven by the instruction currently being executed).

Von Neumann vs Harvard architecture

Von Neumann (stored-program)

Single shared memory holds both instructions and data, accessed over a single bus. Simple and cheap, but the CPU cannot fetch an instruction and read/write data in the same cycle — this single shared bus is the "von Neumann bottleneck."

Harvard architecture

Separate memories (and buses) for instructions and data, so instruction fetch and data access can happen in the same clock cycle. Used inside modern CPUs at the cache level (separate I-cache and D-cache) even though main memory is logically von Neumann.

GATE trap

Most GATE questions describe a "modified Harvard" architecture without naming it: split L1 instruction/data caches feeding a single unified main memory. Don't assume pure Harvard just because caches are split — check what main memory looks like.

Bus organization

A bus is a shared set of wires carrying address, data, and control signals between units. Because only one device can drive the bus at a time, bus width and bus arbitration directly bound system performance.

Single bus

One shared bus for everything — cheap, simple, but only one transfer can happen at a time (a structural bottleneck, closely related to pipeline structural hazards in Section 08).

Multiple/dedicated buses

Separate address, data, and control lines (or separate buses per functional unit) allow overlapped transfers — higher throughput at higher hardware cost.

Bus typeCarriesDirection
Address busMemory/IO location to accessUnidirectional (CPU → memory)
Data busActual operand/instruction bitsBidirectional
Control busRead/Write, clock, interrupt, ready signalsMixed
Address bus width ↔ address space

An address bus of n bits can address exactly 2ⁿ distinct locations. A data bus of w bits moves w bits per transfer — so a 32-bit address bus with an 8-bit-addressable memory gives 2³² bytes = 4 GB of address space, regardless of the data bus width.

Register Transfer Language (RTL)

Micro-operations — the elementary steps a CPU performs each clock cycle — are written using RTL notation. A transfer R2 ← R1 means "the content of R1 is copied into R2, source unchanged." Arithmetic/logic micro-ops combine transfers with operators: R3 ← R1 + R2.

MAR ← PC ; address of next instruction loaded into Memory Address Register MDR ← M[MAR] ; memory read into Memory Data Register IR ← MDR ; instruction latched into Instruction Register PC ← PC + 1 ; program counter advances to next instruction
Key CPU registers

PC (Program Counter) — address of the next instruction. IR (Instruction Register) — currently executing instruction. MAR — address sent to memory. MDR/MBR — data being transferred to/from memory. Accumulator/GPRs — general operand storage.

Practice — GATE style (original)

5 questions
Q1 Why can't a pure von Neumann machine fetch the next instruction and access data in the same cycle?

Instructions and data share one memory and one bus in the von Neumann model, so only one memory access — either the instruction fetch or the data access — can use that shared path in a given cycle.

Answer: They compete for the same single memory/bus (the von Neumann bottleneck)

Q2 A system has a 24-bit address bus and is byte-addressable. What is its maximum addressable memory?

Address space = 2ⁿ locations for an n-bit address bus. 2²⁴ = 16,777,216 bytes.

Answer: 16 MB (2²⁴ bytes)

Q3 In RTL, what does the micro-operation sequence "MAR ← PC; MDR ← M[MAR]; IR ← MDR" collectively accomplish?

The PC's value (address of the next instruction) is copied to MAR, that address is used to read memory into MDR, and MDR's content is then latched into IR — this is exactly the instruction-fetch micro-operation sequence.

Answer: Instruction fetch (fetching the next instruction from memory into IR)

Q4 Why do modern CPUs use separate instruction and data caches (Harvard-style) even though main memory is unified (von Neumann)?

Splitting only the fastest, closest level of the memory hierarchy lets the pipeline fetch an instruction and access data in the same cycle without the cost of fully duplicating main memory — the "modified Harvard" compromise.

Answer: To remove the single-bus fetch/access bottleneck at the cache level without duplicating all of main memory

Q5 A single shared bus connects CPU, memory, and I/O. What is the main performance disadvantage of this design over a multi-bus design?

Because only one device can drive the shared bus at any instant, all transfers — CPU↔memory, CPU↔I/O, and any DMA transfer — must serialize on that one bus, so no two transfers can overlap in time.

Answer: Only one transfer can occur at a time (a structural bottleneck), unlike multi-bus designs that allow overlap

Instruction Set & Addressing Modes

INSTRUCTION FORMATS · OPERAND COUNT · ADDRESSING MODES · CISC vs RISC

Instruction formats by operand count

An instruction set's "architecture family" is usually described by how many explicit operands its ALU instructions take.

TypeFormExample (A = B + C)
0-address (stack)opcode onlyPUSH B; PUSH C; ADD; POP A
1-address (accumulator)opcode, 1 operandLOAD B; ADD C; STORE A
2-addressopcode, dest=src opMOV A,B; ADD A,C
3-addressopcode, dest, src1, src2ADD A,B,C
Trade-off

Fewer operands per instruction ⇒ shorter, denser instructions but more total instructions (and more memory traffic) needed for the same computation. 0-address code is smallest per-instruction but needs the most instructions; 3-address is the opposite.

Addressing modes

An addressing mode is the rule for computing the effective address (EA) — the actual memory/register location an operand comes from — out of the bits given in the instruction.

Displacement / indexedEA = register + offsetBase+index addressing; arrays, records
PC-relativeEA = PC + offsetPosition-independent branches
Autoincrement/decrementEA = register, then register ± sizeSequential array traversal, stack push/pop
GATE trap

Indirect addressing needs two memory references (one to fetch the pointer, one to fetch the actual operand) — GATE frequently asks for the total number of memory accesses across a chain of nested indirections; count each hop.

CISC vs RISC

CISC

Large, variable-length instruction set; complex instructions can directly access memory (memory-to-memory operations); microprogrammed control is typical; fewer instructions per program but more cycles per instruction on average.

RISC

Small, fixed-length, uniform instruction set; load-store architecture — only LOAD/STORE touch memory, all ALU ops are register-to-register; simple instructions enable hardwired control and efficient pipelining.

FeatureCISCRISC
Instruction lengthVariableFixed

Control unitUsually microprogrammedUsually hardwired
Addressing modesManyFew
PipeliningHarder (variable timing)Easier (uniform timing)
Examplex86ARM, RISC-V, MIPS
Instruction length vs opcode/operand split

For a fixed instruction word of n bits with k operand fields of m bits each, the opcode gets n − k·m bits, allowing up to 2^(n−k·m) distinct instructions — a very common GATE numerical.

Practice — GATE style (original)

5 questions
Q1 Compute A = B + C using strictly 1-address (accumulator) instructions.

An accumulator machine implicitly uses the accumulator as one operand and the destination. LOAD B (Acc ← B); ADD C (Acc ← Acc + C); STORE A (A ← Acc).

Answer: LOAD B; ADD C; STORE A (3 instructions)

Q2 An instruction uses double (2-level) indirect addressing. How many memory references does fetching the operand require, not counting the instruction fetch itself?

Level 1: read memory at the address field to get a pointer. Level 2: read memory at that pointer to get a second pointer. Level 3: read memory at that second pointer to get the actual operand — double indirection means the address field points to a pointer to a pointer.

Answer: 3 memory references

Q3 An instruction word is 16 bits with one opcode field and two 5-bit register-operand fields. How many distinct opcodes can this format support?

Operand fields consume 2 × 5 = 10 bits, leaving 16 − 10 = 6 bits for the opcode. 6 bits give 2⁶ = 64 distinct opcodes.

Answer: 64 opcodes

Q4 Why is a load-store (RISC) architecture generally easier to pipeline than one where ALU instructions can operate directly on memory?

When every instruction takes a uniform, predictable number of cycles (register-to-register ALU ops, with memory touched only by LOAD/STORE) the pipeline stages stay balanced; instructions that unpredictably combine memory access with ALU computation cause variable-length stages and stalls.

Answer: Uniform instruction timing avoids the variable-latency stalls that memory-operand ALU instructions cause

Q5 An array element access uses "base register + index register + constant offset" to form its effective address. Which addressing mode is this closest to, and why is it useful for arrays?

This is base-indexed (displacement/indexed) addressing generalized with two registers — the base register holds the array's start address, the index register holds the running element position, and the constant offset can select a field within a record, letting one instruction template walk an entire array or array-of-structs.

Answer: Indexed (base + index + displacement) addressing — avoids recomputing a new absolute address for every element

03

Design of the Arithmetic-Logic Unit (ALU)

ADDERS · MULTIPLIERS · BOOTH'S ALGORITHM · RESTORING DIVISION

Adder circuits — the ALU's core building block

Ripple carry adder (RCA)

Chain of n full adders, each waiting for the carry-out of the previous stage. Simple and cheap in hardware, but worst-case delay is O(n) — the carry must ripple through every stage.

Carry look-ahead adder (CLA)

Computes all carries in parallel from generate/propagate signals, cutting delay to O(log n) at the cost of more gates. Generate Gᵢ = AᵢBᵢ (a carry is produced regardless of Cin); propagate Pᵢ = Aᵢ⊕Bᵢ (an incoming carry passes through).

Cᵢ₊₁ = Gᵢ + Pᵢ·Cᵢ (recurrence used by every carry stage) C₁ = G₀ + P₀C₀ C₂ = G₁ + P₁G₀ + P₁P₀C₀ C₃ = G₂ + P₂G₁ + P₂P₁G₀ + P₂P₁P₀C₀ ← each Cᵢ expands directly in terms of C₀, no rippling
GATE trap

RCA delay of an n-bit adder is quoted as n·Δ (Δ = single full-adder delay) or sometimes 2n·Δ depending on whether the question counts gate levels or full-adder stages — always check which delay model the question specifies before plugging in n.

Multiplication — array & sequential multipliers

Unsigned multiplication of two n-bit numbers is fundamentally repeated add-and-shift: for each multiplier bit that is 1, add the (shifted) multiplicand into a running partial-product sum.

Array multiplier

A 2-D grid of AND gates and adders computes all partial products in parallel and sums them combinationally — fast but hardware grows as O(n²).

Sequential (shift-add) multiplier

One partial product generated and added per cycle using a single adder, product register, and shift register — takes n cycles for n-bit operands but far less hardware.

Booth's algorithm — signed multiplication

Booth's algorithm multiplies signed (2's complement) numbers directly, without separate sign handling, and speeds up runs of consecutive 1s or 0s in the multiplier by treating them as a single subtract/add at the boundary.

Booth's recoding rule (examine Qₙ, Qₙ₋₁)
Qₙ Qₙ₋₁Operation on A (accumulator)
00No operation (run of 0s continues)
01A ← A + M (end of a run of 1s)
10A ← A − M (start of a run of 1s)
11No operation (run of 1s continues)

After each step, arithmetic-shift-right the combined (A, Q, Qₙ₋₁) register. Repeat n times for n-bit operands.

Why Booth's helps

A long run of 1s in the multiplier (e.g. 0111110) needs 5 additions the naive way, but Booth's collapses it to one subtraction at the run's start and one addition at its end — fewer arithmetic operations for multipliers with long runs of consecutive equal bits.

Worked example

Multiply M = +3 (multiplicand) by Q = −4 (multiplier) using 4-bit registers. Expected result: 3 × (−4) = −12.

Initial state — A = 0000, Q = 1100, Qₙ₋₁ = 0, M = 0011 (and −M = 1101 for subtraction):

CycleQₙ Qₙ₋₁ActionA after actionA, Q, Qₙ₋₁ after shift
10, 0none00000000 0110 0
20, 0none00000000 0011 0
31, 0A ← A − M11011110 1001 1
41, 1none11101111 0100 1

After 4 cycles (= number of bits), the product is the concatenation A:Q = 1111 0100, an 8-bit 2's complement number. Converting: invert (0000 1011) and add 1 → 0000 1100 = 12, so the value is −12.

Answer: A:Q = 1111 0100 = −12 ✓ matches 3 × (−4)

Restoring division

Restoring division subtracts the divisor from a running partial remainder; if the result goes negative, it restores the previous remainder (adds the divisor back) and records quotient bit 0, otherwise it keeps the result and records quotient bit 1 — one iteration per quotient bit, shifting left each round.

Non-restoring division

Skips the explicit restore step by choosing to add or subtract the divisor on the next iteration based on the current remainder's sign — same number of iterations, fewer total add/subtract operations than restoring division.

Logic operations & the ALU's functional structure

Besides arithmetic, an ALU implements bitwise AND, OR, XOR, NOT, and shift/rotate operations. A function-select input chooses which operation's result is routed to the output — typically via a multiplexer fed by parallel arithmetic and logic sub-units.

Practice — GATE style (original)

5 questions
Q1 A 16-bit ripple carry adder is built from full adders, each with a 2 ns worst-case delay. What is the worst-case time for the sum to stabilize?

In the worst case (a carry generated at the LSB must ripple through all 16 stages), total delay = number of stages × per-stage delay = 16 × 2 ns.

Answer: 32 ns

Q2 Using Booth's algorithm, how many arithmetic (add/subtract) operations are triggered while multiplying by the multiplier 0 1 1 1 1 0 (reading Qₙ,Qₙ₋₁ pairs left to right)?

Scanning bit pairs across 011110 with an implicit 0 appended on the right: the transition from 0 to the run of 1s triggers one subtract (10), and the transition from the run of 1s back to 0 triggers one add (01); the interior 11 pairs and the boundary 00 trigger nothing.

Answer: 2 operations (one subtract, one add) — instead of 4 additions the naive way

Q3 In a carry look-ahead adder, express the carry-out of bit position 2 (C₂) purely in terms of C₀ and the generate/propagate signals.

Each carry recurrence Cᵢ₊₁ = Gᵢ + PᵢCᵢ is expanded backward to C₀ so no stage waits on the previous stage's carry: C₂ = G₁ + P₁C₁ = G₁ + P₁(G₀ + P₀C₀) = G₁ + P₁G₀ + P₁P₀C₀.

Answer: C₂ = G₁ + P₁G₀ + P₁P₀C₀

Q4 What is the main hardware trade-off of an array multiplier versus a sequential shift-add multiplier for n-bit operands?

An array multiplier lays out all partial-product generation and summation combinationally, so it needs roughly O(n²) adder/gate hardware but produces the result in one combinational pass; a sequential multiplier reuses a single adder over n cycles, needing far less hardware but n times the latency.

Answer: Array multiplier trades O(n²) hardware for speed; sequential multiplier trades n cycles of latency for minimal hardware

Q5 In restoring division, what action is taken when a trial subtraction of the divisor from the partial remainder produces a negative result?

A negative trial result means the divisor didn't fit at this step, so the algorithm restores the partial remainder by adding the divisor back (undoing the trial subtraction) and records a quotient bit of 0 for this iteration.

Answer: Add the divisor back to restore the remainder, and set the quotient bit to 0

Datapath & Instruction Cycle

FETCH-DECODE-EXECUTE · SINGLE-CYCLE vs MULTI-CYCLE · CPI

The instruction cycle

Every instruction, regardless of ISA, moves through the same broad phases every time it executes:

Fetch

IR ← M[PC]; PC ← PC + (instruction size). The instruction word is read from memory into the instruction register and PC advances to the next instruction.

Decode

Control unit interprets the opcode and operand fields, determining which datapath control signals to assert for this specific instruction.

Operand fetch / Execute

Registers or memory operands are read, the ALU performs the required computation (or a branch condition is evaluated).

Memory / Writeback

Memory is accessed if the instruction is a LOAD/STORE, and the result (if any) is written back into a register.

Single-cycle vs multi-cycle datapath

AspectSingle-cycleMulti-cycle
Clock periodFixed, set by the slowest instructionFixed per micro-step, shorter than single-cycle's period
Cycles per instruction (CPI)Always 1Varies (e.g. 3–5) by instruction type
Hardware reuseSeparate adders/ALU uses can't be shared within an instructionSame ALU can be reused across multiple steps of one instruction
Total execution timeEvery instruction is as slow as the slowest oneSimple instructions finish faster in wall-clock time
GATE trap

A single-cycle datapath having CPI = 1 does not mean it is faster overall — its clock period must accommodate the worst-case (usually LOAD, which touches register read, ALU address computation, memory access, and writeback all in one cycle), so its per-instruction time can exceed a well-pipelined or multi-cycle design's average.

Performance: CPI, clock rate, and execution time

Core performance equation
CPU time = Instruction count × CPI × Clock cycle time = (Instruction count × CPI) / Clock rate

When a program mixes instruction types with different CPIs, use the weighted average CPI: Σ(fraction of instruction type × its CPI) across all types.

MIPS as a metric

MIPS = Clock rate / (CPI × 10⁶). MIPS is a flawed comparison metric across different instruction sets (a "MIPS-inflated" ISA using many cheap instructions can look faster while doing less useful work per instruction) — GATE sometimes uses this to test whether you compare instruction counts too, not just MIPS.

Practice — GATE style (original)

5 questions
Q1 A program has 40% ALU instructions (CPI=1), 30% LOAD/STORE (CPI=3), and 30% branches (CPI=2). What is the average CPI?

Weighted average CPI = Σ (fraction × CPI) = 0.4×1 + 0.3×3 + 0.3×2 = 0.4 + 0.9 + 0.6 = 1.9.

Answer: 1.9

Q2 A CPU runs at 2 GHz, executes a program with 10⁹ instructions at an average CPI of 1.5. What is the execution time?

CPU time = (Instruction count × CPI) / Clock rate = (10⁹ × 1.5) / (2×10⁹) = 1.5/2 = 0.75 seconds.

Answer: 0.75 seconds

Q3 Why must a single-cycle datapath's clock period be set by the slowest instruction (typically LOAD) rather than the average instruction?

In a single-cycle design every instruction — fast or slow — must fully complete within exactly one clock period, so the clock period has to be long enough for the worst-case instruction's critical path or the slower instructions would produce wrong results.

Answer: All instructions share one fixed-length cycle, so the cycle must accommodate the worst-case (slowest) instruction

Q4 A multi-cycle CPU takes 4 cycles for ALU ops and 5 cycles for LOAD, with a 250 MHz clock. If a program is 50% ALU and 50% LOAD instructions totaling 200 instructions, find the total execution time.

Average CPI = 0.5×4 + 0.5×5 = 4.5. Total cycles = 200 × 4.5 = 900. Clock period = 1/(250×10⁶) = 4 ns. Execution time = 900 × 4 ns = 3600 ns.

Answer: 3600 ns (3.6 μs)

Q5 Two CPUs run the same program: CPU A has a higher MIPS rating than CPU B. Does that guarantee A finishes the program faster?

MIPS only reflects instructions executed per second, not the actual work done per instruction — if CPU A's compiler generates more instructions to do the same job (a less efficient ISA or code generation), A can have higher MIPS yet still take more total time than B.

Answer: No — MIPS ignores instruction count differences and can be misleading across different ISAs/compilers

Control Unit Design — Hardwired & Microprogrammed

HARDWIRED CONTROL · MICROPROGRAMMING · CONTROL WORD · HORIZONTAL vs VERTICAL

What the control unit does

The control unit generates the sequence of control signals (register-enable, ALU-function-select, memory-read/write, etc.) needed to execute each instruction's micro-operations in the right order and at the right time, driven by the opcode in IR and the current step of the instruction cycle.

Hardwired control

How it works

Control signals are produced directly by combinational logic (and a state/step counter) built from the opcode bits, condition flags, and the current cycle count — essentially a custom finite state machine (see the FSM design ideas from Digital Logic) realized in gates.

PropertyHardwired
SpeedFast — pure combinational logic, no memory lookup
FlexibilityLow — adding/changing an instruction means redesigning logic
Typical useRISC processors (small, regular instruction sets)
Complexity growthGrows rapidly (and irregularly) with instruction set size

Microprogrammed control

How it works

Each machine instruction is implemented as a small program — a sequence of microinstructions stored in a fast control store (ROM/RAM). Each microinstruction contains a control word whose bits directly (or indirectly) drive the datapath's control signals for one micro-step.

Horizontal microinstruction

One bit per control signal — wide control word, no decoding needed, but very large control store. Allows maximum parallelism (many signals asserted at once).

Vertical microinstruction

Encoded fields (like a mini-opcode) that must be decoded to produce actual control signals — narrower control word, smaller control store, but needs a decoder and allows less parallelism per microinstruction.

Micro-program sequencing

Besides its control-signal field(s), each microinstruction carries addressing information for the next microinstruction — a simple increment for straight-line sequences, or a branch/jump (often conditioned on opcode bits or status flags) to implement per-instruction control flow, exactly the way a tiny CPU-within-a-CPU would.

Worked example — sizing a control store

A control store holds 512 microinstructions. Each microinstruction is 32 bits wide: a 23-bit control field plus a 9-bit next-address field. Is the next-address field wide enough, and what is the total control store size?

Minimum next-address bits needed = ⌈log₂(512)⌉ = 9 bits → 9 bits given, exactly sufficient (2⁹ = 512) Total control store size = (number of microinstructions) × (bits per microinstruction) = 512 × 32 bits = 16,384 bits = 2,048 bytes = 2 KB

Answer: 9-bit next-address field is exactly sufficient; total control store size = 2 KB

Where this trips people up

If the next-address field had been only 8 bits, 2⁸ = 256 locations could be addressed — not enough to reach all 512 microinstructions, meaning some of the store would be unreachable by a jump/branch microinstruction. Always check the next-address field width against the store size before computing total bits — GATE sometimes gives an under-sized field on purpose.

PropertyMicroprogrammed
SpeedSlower — every control signal costs a control-store access
FlexibilityHigh — new/modified instructions just need new microcode, no redesign
Typical useCISC processors (large, irregular instruction sets)
Ease of debugging/updatingEasy — microcode can be patched (even in the field, via microcode updates)
GATE trap

"Horizontal" and "vertical" describe the microinstruction encoding, not the control unit type. A microprogrammed control unit can use either style. Also: hardwired is faster but rigid; microprogrammed is slower but flexible — GATE loves to test this exact trade-off with reworded distractors.

Practice — GATE style (original)

5 questions
Q1 Why is hardwired control generally faster than microprogrammed control?

Hardwired control produces signals directly from combinational logic gates reacting to the opcode, while microprogrammed control must first read a microinstruction out of a control store (a memory access) before that signal can be produced.

Answer: Hardwired uses direct combinational logic; microprogrammed pays a control-store memory-access delay per step

Q2 A design team needs to add five new specialized instructions to an existing CPU without a hardware redesign. Which control unit style makes this feasible, and why?

Microprogrammed control implements instructions as microcode routines in the control store — adding a new instruction just means writing new microinstructions and updating the sequencing logic that dispatches to them, with no change to the underlying combinational hardware.

Answer: Microprogrammed control — new instructions are added as new microcode, not new logic gates

Q3 A control store holds horizontal microinstructions with one bit per control signal, for 40 distinct control signals. How many bits wide is the control field of each microinstruction?

By definition, a horizontal microinstruction dedicates exactly one bit to each control signal with no encoding/sharing, so the control field width equals the number of distinct signals.

Answer: 40 bits

Q4 A vertical microinstruction format encodes control signals into a 6-bit field that must be decoded by an external decoder. At most how many distinct control-signal combinations can this field select?

A 6-bit encoded field can represent 2⁶ distinct binary patterns, each of which the decoder maps to one control-signal combination.

Answer: 64 combinations

Q5 Why do RISC processors typically favor hardwired control while CISC processors typically favor microprogrammed control?

RISC's small, regular, fixed-format instruction set keeps the combinational logic for hardwired control manageable and fast, matching RISC's speed goals; CISC's large, irregular instruction set (many addressing modes, memory-to-memory ops) would make hardwired logic explode in complexity, so microcode's flexibility is worth its extra latency.

Answer: RISC's simple, uniform ISA suits fast hardwired logic; CISC's complex, irregular ISA suits flexible microcode

Memory Interfacing & Hierarchy

HIERARCHY PERFORMANCE · CACHE MAPPING · HIT/MISS · AAT

Why a memory hierarchy exists

Registers are tiny and fast; main memory (DRAM) is large but slow; the gap between CPU speed and memory speed is bridged with progressively larger, slower cache levels (L1 → L2 → L3) that exploit temporal locality (recently used data is likely reused soon) and spatial locality (nearby addresses are likely accessed soon).

LevelTypical sizeTypical latency
Registers< 1 KB< 1 cycle
L1 cache16–64 KB~1–4 cycles
L2/L3 cache256 KB–tens of MB~10–40 cycles
Main memory (DRAM)GBs~100–300 cycles

Cache mapping techniques

A memory block must be located somewhere in cache using an address split into tag | index | offset fields. The mapping technique decides which cache line(s) a block is allowed to occupy.

Direct mapped

Each memory block maps to exactly one specific cache line: line = (block address) mod (number of lines). Simple and fast, but suffers conflict misses when two frequently used blocks map to the same line.

Fully associative

A block can go in any cache line — no conflict misses from mapping, but every line's tag must be compared in parallel (expensive comparator hardware), and a replacement policy (e.g. LRU) is needed.

Set-associative (k-way)

A middle ground: cache is divided into sets, each set holding k lines. A block maps to exactly one set (set = block address mod number of sets) but can occupy any of the k lines within that set. Direct mapped is 1-way set-associative; fully associative is the limiting case where there is only 1 set.

Address split (for a set-associative cache)
Offset bits = log₂(block size in bytes) Index bits = log₂(number of sets) Tag bits = (total address bits) − Index bits − Offset bits
GATE trap

The index field selects the set, not a single line — for set-associative caches, once the correct set is found, the tags of all ways within that set are compared in parallel against the address tag to find a hit. Don't confuse "number of sets" with "number of lines" when computing index bits.

Worked example — tracing hits and misses

A direct-mapped cache has 4 lines (0–3), one block per line, initially empty. The CPU accesses these block addresses in order: 0, 1, 2, 3, 4, 0, 1, 4, 0, 3. Since it's direct-mapped, line = block address mod 4.

Replacement & write policies

Replacement (associative/set-associative)

LRU (evict least-recently-used line — best locality match, costliest to implement exactly), FIFO, and Random are the classic choices.

Write policy

Write-through: every write updates cache and memory immediately (simpler, more memory traffic). Write-back: writes update only the cache line (marked dirty); memory is updated only when that line is evicted (less traffic, but needs a dirty bit and more complex control).

Average access time (AAT) & hierarchy performance

Average Access Time
AAT = Hit time + Miss rate × Miss penalty For a 2-level hierarchy (L1 backed by main memory): AAT = H1 + M1 × MP1 where H1 = L1 hit time, M1 = L1 miss rate, MP1 = L1 miss penalty (≈ memory access time)

For multi-level caches this nests: the "miss penalty" of L1 is itself the AAT of the L2/memory system below it.

Practice — GATE style (original)

5 questions
Q1 A cache has 256 sets, 4-way set-associative, with a 64-byte block size, on a 32-bit address. Find the number of tag, index, and offset bits.

Offset bits = log₂(64) = 6. Index bits = log₂(256) = 8. Tag bits = 32 − 8 − 6 = 18.

Answer: Tag = 18 bits, Index = 8 bits, Offset = 6 bits

Q2 A system has L1 hit time 2 ns, L1 miss rate 5%, and a miss penalty (main memory access) of 100 ns. What is the average access time?

AAT = Hit time + Miss rate × Miss penalty = 2 + 0.05 × 100 = 2 + 5 = 7 ns.

Answer: 7 ns

Q3 Why does a fully associative cache eliminate conflict misses that a direct-mapped cache of the same total size would suffer?

In a direct-mapped cache each block is forced into exactly one specific line, so two frequently-accessed blocks mapping to the same line will keep evicting each other; a fully associative cache lets any block occupy any line, so capacity — not a rigid mapping rule — is the only limit on what stays resident.

Answer: Because any block can occupy any line, so no two blocks are forced to contend for one fixed line

Q4 Between write-through and write-back policies, which generates more memory bus traffic, and why?

Write-through sends every single write to memory immediately regardless of how many times that location is subsequently overwritten in cache, whereas write-back accumulates multiple writes to the same cache line and sends only one memory update, when the line is eventually evicted.

Answer: Write-through generates more traffic — every write goes to memory, not just evictions

Q5 In a 2-way set-associative cache lookup, once the index selects a set, how many tag comparisons happen in parallel, and what determines a hit?

A 2-way set holds 2 lines, so both lines' stored tags are compared simultaneously against the incoming address's tag field; a hit occurs if either comparison matches and that line's valid bit is set.

Answer: 2 parallel tag comparisons; a hit occurs on a matching tag with the valid bit set in either way

I/O Interface — Interrupts & DMA

PROGRAMMED I/O · INTERRUPT-DRIVEN I/O · DMA · CYCLE STEALING

Three ways the CPU talks to I/O devices

Programmed I/O (polling)

CPU repeatedly polls a device's status register in a busy-wait loop until it's ready, then transfers data itself. Simple, but wastes CPU cycles busy-waiting — the CPU cannot do other useful work while polling.

Interrupt-driven I/O

CPU issues the I/O request and continues other work; the device raises an interrupt when it's ready, and the CPU (after finishing its current instruction) suspends its program, runs an interrupt service routine (ISR) to handle the transfer, then resumes. Removes busy-waiting, but each transfer still costs a full CPU context switch to and from the ISR.

Direct Memory Access (DMA)

A dedicated DMA controller transfers an entire block of data directly between the I/O device and memory without CPU involvement for each word — the CPU only sets up the transfer (source, destination, count) and is interrupted once when the whole block is done.

Interrupt handling mechanics

Vectored interrupts

The interrupting device itself supplies the address of its ISR (the "interrupt vector") — fast dispatch, no need to poll each device to find the source.

Non-vectored / polled interrupts

All devices share a single interrupt line; the CPU must poll each device's status in priority order to discover which one interrupted — simpler hardware, slower dispatch.

What "handling an interrupt" actually costs

On an interrupt, the CPU must save its current context (PC and often other registers/flags) onto the stack, jump to the ISR, execute it, then restore the saved context and resume — this save/restore overhead is exactly why interrupt-driven I/O still isn't free, and why DMA (only one interrupt per whole block) is preferred for bulk transfers.

DMA transfer modes

ModeHow it shares the bus with the CPU
Burst (block) modeDMA controller holds the bus and transfers the entire block at once; CPU is locked out until the transfer completes
Cycle stealingDMA controller transfers one word, then releases the bus for one CPU cycle, repeating — CPU and DMA interleave, slowing the CPU slightly but not blocking it entirely
Transparent (interleaved) modeDMA only uses bus cycles the CPU isn't using — zero CPU slowdown, but requires the DMA controller to synchronize with idle cycles
GATE trap

DMA still needs the system bus to move data, so it does contend with the CPU for bus cycles (except in transparent mode) — DMA removes per-word CPU instruction overhead, not bus contention. Don't assume DMA is "free"; it just moves the cost from CPU cycles to bus cycles.

Practice — GATE style (original)

5 questions
Q1 Why is programmed I/O (polling) inefficient for a slow device like a keyboard?

The CPU must repeatedly check the device's status in a busy-wait loop until it becomes ready, and since a keyboard is extremely slow relative to CPU speed, the vast majority of those polling cycles are wasted doing no useful work.

Answer: The CPU busy-waits, wasting cycles that could run other programs while the slow device isn't ready

Q2 A 1 MB block must be transferred from disk to memory. Compare, at a high level, how many times the CPU is interrupted under interrupt-driven I/O (word-at-a-time) versus DMA.

Interrupt-driven I/O interrupts the CPU once per unit transferred, so a 1 MB transfer at, say, one word per interrupt would need one interrupt per word; DMA only interrupts the CPU once, after the entire block transfer completes.

Answer: Interrupt-driven I/O interrupts once per word transferred; DMA interrupts only once for the whole block

Q3 What is the key advantage of vectored interrupts over non-vectored (polled) interrupts when multiple devices share the interrupt line?

With vectored interrupts the device itself supplies its ISR address directly, so the CPU jumps straight to the correct handler; with non-vectored interrupts the CPU must poll each device in turn to find which one raised the interrupt, adding dispatch latency.

Answer: Vectored interrupts let the CPU dispatch directly to the correct ISR without polling every device

Q4 In cycle-stealing DMA, why does the CPU slow down slightly rather than stop completely, unlike burst-mode DMA?

Cycle stealing has the DMA controller take just one bus cycle at a time and then release the bus back, so the CPU only loses isolated individual cycles rather than being locked out for the whole transfer duration as it would be in burst mode.

Answer: DMA takes the bus only one cycle at a time and releases it back, interleaving with the CPU instead of blocking it

Q5 List, in order, the essential steps the CPU performs when handling an interrupt (from the moment the interrupt line is asserted to resuming the interrupted program).

The CPU finishes its current instruction, saves its context (PC and status/registers) onto the stack, identifies the interrupt source and jumps to the corresponding ISR, executes the ISR, then restores the saved context and resumes the interrupted program from where it left off.

Answer: Finish current instruction → save context → dispatch to ISR → execute ISR → restore context → resume

Instruction Pipelining & Pipeline Hazards

5-STAGE PIPELINE · STRUCTURAL/DATA/CONTROL HAZARDS · FORWARDING · AMDAHL'S LAW

The classic 5-stage pipeline

Pipelining overlaps the execution of successive instructions by splitting the instruction cycle into stages, each handled by dedicated hardware, so a new instruction can enter the pipeline every cycle once it's full.

IFInstruction Fetch
IDDecode / Reg Read
EXExecute (ALU)
MEMMemory Access
WBWrite Back
Ideal pipeline speedup
Time for n instructions, k stages, cycle time T: Non-pipelined: n × k × T Pipelined: (k + n − 1) × T Speedup (n → ∞) → k (approaches the number of stages)

Each instruction advances one stage per cycle; a new instruction enters IF every cycle once the pipeline is full. Total cycles = k + n − 1 = 5 + 5 − 1 = 9.

Structural hazards

Two instructions need the same hardware resource in the same cycle — classic example: a single shared memory used for both instruction fetch (IF) and data memory access (MEM) by different instructions in the same cycle. Fix: duplicate the resource (e.g. separate I-cache/D-cache, as in Section 01's modified Harvard idea).

Data hazards

An instruction needs a value that a previous, still-in-flight instruction hasn't produced yet.

TypePatternOccurs when
RAW (Read After Write)I2 reads what I1 writesTrue dependency — I2 needs I1's result before I1 has produced it
WAR (Write After Read)I2 writes what I1 readsOnly in out-of-order execution — I1 must read before I2 overwrites
WAW (Write After Write)I2 writes what I1 also writesOnly in out-of-order execution — final value must reflect program order

Fix 1: Stalling

Insert bubbles (NOPs) into the pipeline until the needed value is ready — simple but wastes cycles.

Fix 2: Forwarding (bypassing)

Route the ALU's result directly from EX/MEM (or MEM/WB) latches back into the EX stage input of a dependent instruction, skipping the need to wait for WB — eliminates most RAW stalls in a simple 5-stage pipeline.

GATE trap

Forwarding cannot eliminate a load-use hazard: if the very next instruction needs a value that a LOAD is still fetching from memory (available only after MEM), even forwarding from MEM/WB isn't early enough — a one-cycle stall is unavoidable unless the compiler reorders code around it.

Timing diagram — load-use hazard with 1 stall

I2 (e.g. ADD R2, R1, R3) needs R1, which I1 (LOAD R1, 0(R4)) doesn't produce until the end of its MEM stage — one cycle too late for I2's EX. The pipeline holds I2 (and everything behind it) for one extra cycle, shown as a bubble:

I2 is held in ID for an extra cycle (its EX is pushed from cycle 4 to cycle 5) and I3's IF is likewise held one cycle, since it can't move into ID while I2 occupies it. Everything downstream shifts by exactly one cycle — total time goes from the ideal 9 cycles to 10.

Control hazards

Caused by branches — the pipeline doesn't know which instruction to fetch next until the branch is resolved (often not until EX or later).

Branch prediction

Guess taken/not-taken (statically or dynamically) and speculatively fetch down that path; flush the pipeline and restart on a misprediction — the "misprediction penalty" equals the number of stages already speculatively executed.

Delayed branch

Compiler fills the instruction slot(s) immediately after a branch with useful, always-executed instructions ("branch delay slots") so the pipeline has real work to do while the branch resolves.

Amdahl's law & pipeline speedup with stalls

Amdahl's Law
Speedup(overall) = 1 / [ (1 − f) + f/S ] f = fraction of execution time that is sped up S = speedup obtained on that fraction

Even if a pipeline speeds up execution enormously, overall speedup is capped by the fraction of time that cannot be sped up — a recurring GATE numerical setup applied to pipelining, parallel processing, and cache improvements alike.

Effective CPI with stalls

Pipelined CPI = Ideal CPI (≈1) + average stall cycles per instruction. If 20% of instructions are loads causing 1 stall cycle each, average stalls per instruction = 0.2 × 1 = 0.2, so pipelined CPI ≈ 1.2.

Practice — GATE style (original)

5 questions
Q1 A 5-stage pipeline with a 2 ns clock period executes 100 instructions with no stalls. How much total time does it take?

Total cycles = k + n − 1 = 5 + 100 − 1 = 104. Total time = 104 × 2 ns = 208 ns.

Answer: 208 ns

Q2 Instruction I2 (ADD R3, R1, R2) immediately follows I1 (SUB R1, R4, R5) in program order. What kind of hazard is this, and can forwarding resolve it in a standard 5-stage pipeline?

I2 reads R1, which I1 is about to write — a true (RAW) data dependency. Since I1's ALU result is available at the end of its EX stage, it can be forwarded directly into I2's EX stage input without waiting for I1 to reach WB.

Answer: RAW hazard; yes, EX-to-EX forwarding resolves it with no stall

Q3 Why can't forwarding alone eliminate a load-use hazard, where the instruction right after a LOAD needs the loaded value?

The loaded value isn't produced until the LOAD instruction's MEM stage completes, but the dependent instruction needs that value as an input to its own EX stage, which happens one cycle before the LOAD's MEM stage finishes — so the data simply doesn't exist yet at the moment it's needed, forwarding or not.

Answer: The value isn't available until after MEM, but the next instruction needs it in EX — one cycle too early even with forwarding

Q4 An application spends 60% of its time in a portion sped up 4× by a new pipeline design, with the rest unaffected. What is the overall speedup by Amdahl's Law?

Speedup = 1 / [(1 − 0.6) + 0.6/4] = 1 / [0.4 + 0.15] = 1 / 0.55 ≈ 1.818.

Answer: ≈ 1.82×

Q5 A pipeline has a base CPI of 1. 25% of instructions are branches with a 3-cycle misprediction penalty, and the branch predictor is wrong 20% of the time. What is the effective CPI?

Stall cycles contributed per instruction = (fraction of branches) × (misprediction rate) × (penalty) = 0.25 × 0.2 × 3 = 0.15. Effective CPI = base CPI + stalls = 1 + 0.15 = 1.15.

Answer: 1.15

Revision Sheet

EVERYTHING ON ONE SCREEN — LAST-MINUTE PASS
Von Neumann vs Harvard

Von Neumann: shared instruction/data memory (one bottleneck bus). Harvard: separate — used inside modern CPUs at cache level.

Addressing modes: mem accesses

Immediate/Register: 0. Direct/Register-indirect: 1. Indirect: 2 (one per pointer hop).

CISC vs RISC

CISC: variable length, memory-to-memory, microprogrammed. RISC: fixed length, load-store only, hardwired, easier to pipeline.

RCA vs CLA delay

Ripple carry: O(n), simple. Carry look-ahead: O(log n), computes carries from G/P signals in parallel.

Booth's recoding (Qₙ Qₙ₋₁)

00/11 → no-op. 01 → A+M (end of 1-run). 10 → A−M (start of 1-run). Then arithmetic-shift-right.

CPU time equation

CPU time = Instruction count × CPI × Cycle time = (IC × CPI)/Clock rate.

Single-cycle vs multi-cycle

Single-cycle: CPI=1 but period set by slowest instruction. Multi-cycle: variable CPI, shorter cycle, reuses hardware across steps.

Hardwired vs microprogrammed

Hardwired: fast, rigid, combinational (RISC). Microprogrammed: slower (control-store access), flexible, control words per micro-step (CISC).

Horizontal vs vertical microcode

Horizontal: 1 bit/signal, wide, no decode, max parallelism. Vertical: encoded field, narrow, needs decoder, less parallelism.

Cache address split

Offset = log₂(block size). Index = log₂(number of sets). Tag = address bits − index − offset.

Direct / set-assoc / fully-assoc

Direct: 1 line per block (conflict misses). Set-assoc: k lines per set. Fully-assoc: any line, needs LRU/FIFO + parallel tag compare.

AAT (2-level)

AAT = Hit time + Miss rate × Miss penalty. Nests for multi-level hierarchies.

Write-through vs write-back

Write-through: updates memory on every write (more traffic, simpler). Write-back: updates only on eviction of a dirty line (less traffic).

Programmed I/O vs Interrupt vs DMA

Programmed: CPU busy-waits. Interrupt: CPU notified per transfer/word. DMA: block transfer with 1 interrupt at the end, CPU offloaded.

DMA bus modes

Burst: locks CPU out until done. Cycle stealing: interleaves 1 word at a time. Transparent: uses only CPU-idle cycles.

Pipeline speedup (ideal)

Time = (k + n − 1) × T for n instructions, k stages. Speedup → k as n → ∞.

Hazard types

Structural: resource conflict (dup. hardware). Data (RAW/WAR/WAW): dependency (stall/forward). Control: branches (predict/delay slot).

Load-use hazard

Forwarding can't fix it — value ready after MEM, needed one cycle earlier in EX. Needs a 1-cycle stall.

Amdahl's Law

Speedup = 1 / [(1−f) + f/S]. Overall gain is capped by the un-sped-up fraction (1−f).

Effective CPI with stalls

Pipelined CPI = Ideal CPI + average stall cycles per instruction (sum stalls weighted by frequency of the causing instruction type).

Practice — rapid-fire mix (original)

5 questions
Q1 A byte-addressable memory has a 20-bit address bus. What is its total addressable memory size?

Address space = 2ⁿ locations for n address bits: 2²⁰ = 1,048,576 bytes.

Answer: 1 MB

Q2 A cache has an AAT of 5 ns, hit time 2 ns, and miss penalty 60 ns. What is the miss rate?

AAT = Hit time + Miss rate × Miss penalty ⇒ 5 = 2 + MR × 60 ⇒ MR = 3/60 = 0.05.

Answer: 5%

Q3 Why does a load-store (RISC-style) architecture simplify hardwired control unit design compared to an ISA allowing memory-to-memory ALU operations?

Restricting memory access to only LOAD/STORE means every ALU instruction has identical, predictable timing (register-to-register), so the combinational control logic driving the datapath doesn't need special-case timing paths for ALU instructions that also touch memory.

Answer: Uniform instruction timing (only LOAD/STORE touch memory) keeps hardwired control logic simple and regular

Q4 A pipeline processes 50 instructions through 4 stages with 1 ns per stage, but suffers 6 total stall cycles from hazards. What is the total execution time?

Ideal cycles = k + n − 1 = 4 + 50 − 1 = 53. With 6 stall cycles added: 53 + 6 = 59 cycles. Total time = 59 × 1 ns = 59 ns.

Answer: 59 ns

Q5 Why is DMA preferred over interrupt-driven I/O for transferring a large disk block into memory?

Interrupt-driven I/O would require the CPU to save/restore context and run an ISR for every unit of data transferred, which is enormous overhead for a large block; DMA lets a separate controller move the entire block and interrupts the CPU only once, at completion, keeping the CPU free for other work throughout the transfer.

Answer: DMA avoids per-word CPU interrupt/context-switch overhead, needing only one interrupt for the whole block
