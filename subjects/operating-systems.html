01

Processes, Threads & System Calls

PROCESS STATES · PCB · CONTEXT SWITCH · THREADS VS PROCESSES

Process state diagram

Every process moves through a fixed set of states during its lifetime:

New → Ready → Running → (Waiting ⟷ Running) → Terminated Ready → Running: scheduler dispatch Running → Ready: timer interrupt / preemption Running → Waiting: I/O or event wait Waiting → Ready: I/O or event completion
The transition GATE tests most

A process can go directly from Running to Waiting (blocking for I/O) but NEVER directly from Waiting to Running — it must always pass through Ready first, to be re-selected by the scheduler.

Process Control Block (PCB) & context switch

The PCB stores everything needed to pause and later resume a process exactly where it left off: process state, program counter, CPU registers, memory-management info, scheduling info, and open file list. A context switch is the act of saving the current process's PCB and loading another's — pure overhead, no useful computation happens during it.

Process vs Thread

AspectProcessThread
Memory spaceOwn separate address spaceShares address space with sibling threads
Creation/switch costExpensive (heavyweight)Cheap (lightweight)
CommunicationNeeds IPC (pipes, shared memory, etc.)Direct — shared memory already
Crash isolationOne process crashing doesn't affect othersOne thread crashing can bring down the whole process

System calls

The only sanctioned way for a user-mode process to request a kernel-mode service (file I/O, process creation, memory allocation). A system call triggers a mode switch — from user mode to kernel mode — which, like a context switch, is pure overhead relative to actual work.

GATE trap

fork() in Unix-like systems returns TWICE — once in the parent (with the child's PID) and once in the child (with return value 0). GATE frequently asks "how many processes are created" or "how many times is X printed" after a sequence of fork() calls — always trace both branches carefully; n fork() calls in sequence create 2ⁿ total processes.

Practice — PYQ style

5 questions
Q1 A program calls fork() twice in sequence (not nested inside a conditional). How many total processes exist after both calls?

Each fork() doubles the number of processes executing the subsequent code. Starting from 1 process: after 1st fork → 2 processes; after 2nd fork (each of those 2 calls it) → 4 processes.

Answer: 4 processes (2² )

Q2 Can a process move directly from the Waiting state to the Running state?

No — a waiting process must first move to Ready when its event/I/O completes, and only then can the scheduler dispatch it to Running.

Answer: No, it must pass through Ready first

Q3 What information is saved in a PCB during a context switch, and why is a context switch considered pure overhead?

The PCB saves process state, program counter, CPU register values, memory-management info, and scheduling info. It's pure overhead because no instructions from either process actually execute during the switch itself — the CPU is busy bookkeeping, not computing.

Answer: State/PC/registers/memory-info/scheduling-info; overhead because no user computation happens during the switch

Q4 Why is thread creation generally cheaper than process creation?

Threads within the same process share the address space, open files, and most other resources — creating a thread mainly needs a new stack and register set, whereas creating a process needs an entirely new address space and duplicated resources.

Answer: Threads share address space/resources, avoiding the duplication a new process requires

Q5 A system call is invoked. What mode transition occurs, and why is this necessary?

The CPU switches from user mode to kernel mode. This is necessary because privileged operations (direct hardware access, memory protection changes, etc.) must go through the kernel, which enforces the actual access checks — user code alone cannot be trusted to perform them safely.

Answer: User mode → kernel mode, to safely perform privileged operations

02

CPU Scheduling

FCFS · SJF · PRIORITY · ROUND ROBIN · TURNAROUND/WAITING TIME NUMERICALS

Key timing definitions — get these exactly right

Turnaround Time (TAT) = Completion Time − Arrival Time Waiting Time (WT) = Turnaround Time − Burst Time Response Time = Time of first CPU allocation − Arrival Time
The single most common numerical mistake

Waiting time is NOT completion time minus arrival time — that's turnaround time. Waiting time subtracts out the actual burst (execution) time too. Confusing these two is the #1 source of wrong answers in GATE scheduling numericals.

Scheduling algorithms — comparison

AlgorithmPreemptive?Selection criterionKey drawback
FCFS (First-Come-First-Served)NoArrival orderConvoy effect (short jobs stuck behind long ones)
SJF (Shortest Job First)NoSmallest burst timeStarvation of long jobs; needs burst time known in advance
SRTF (Shortest Remaining Time First)YesSmallest remaining burst timeSame starvation risk, plus frequent context switches
Priority SchedulingEitherHighest priorityStarvation of low-priority processes (fixed via aging)
Round RobinYesFixed time quantum, cyclic orderToo-small quantum ⟹ excessive context-switch overhead
Provably optimal (average waiting time)

Among non-preemptive algorithms, SJF minimizes average waiting time — this is a mathematically provable result GATE occasionally asks you to justify or apply directly.

Worked example — FCFS

Process Arrival Burst P1 0 5 P2 1 3 P3 2 8 FCFS order: P1, P2, P3 (by arrival) P1: starts 0, ends 5 → TAT=5, WT=0 P2: starts 5, ends 8 → TAT=7, WT=4 P3: starts 8, ends 16 → TAT=14, WT=6 Average WT = (0+4+6)/3 = 3.33
GATE trap

Round Robin's average waiting time is highly sensitive to the time quantum — too large approaches FCFS behavior (and its convoy effect), too small causes excessive context-switch overhead. GATE often asks for the "ideal" quantum reasoning: a good quantum is slightly larger than the average burst time, not the smallest possible value.

Practice — PYQ style

5 questions
Q1 P1(AT=0,BT=6), P2(AT=1,BT=4), P3(AT=2,BT=2). Using non-preemptive SJF, find the execution order.

At t=0, only P1 has arrived, so it must start (SJF is non-preemptive, so once started it runs to completion). At t=6, P2(BT4) and P3(BT2) have both arrived — pick smaller: P3, then P2.

Answer: P1 → P3 → P2

Q2 For P1(AT=0,BT=4), P2(AT=0,BT=3) under FCFS (P1 first), find the waiting time of P2.

P1 runs 0→4 (WT=0). P2 starts at 4, completes at 4+3=7. TAT of P2 = 7−0=7. WT = TAT − BT = 7−3.

Answer: WT(P2) = 4

Q3 Two processes P1(BT=10) and P2(BT=2) both arrive at t=0. Round Robin with quantum=4. Trace the schedule and find P2's waiting time.

t=0-4: P1 runs (6 remaining). t=4-6: P2 runs to completion (BT=2, finishes at t=6). P2 never waited before its only run — it started immediately at t=4, after waiting 4 units (P1's first quantum).

Answer: WT(P2) = 4

Q4 Why does SJF risk starvation, and what does Round Robin guarantee that SJF does not?

SJF always favors shorter jobs, so a long job can be perpetually pushed back if shorter jobs keep arriving — no upper bound on its wait. Round Robin, by cycling through all ready processes with a fixed quantum, guarantees every process gets CPU time within one full cycle — bounding maximum wait.

Answer: SJF can starve long jobs indefinitely; RR guarantees bounded wait via fair cycling

Q5 P1(AT=0,BT=8) and P2(AT=1,BT=4) with SRTF (preemptive). At what time (if any) does preemption occur, and why?

At t=1, P1 has 7 units remaining while newly-arrived P2 needs only 4. Since SRTF always picks the smallest REMAINING time, P2 preempts P1 at t=1.

Answer: Preemption occurs at t=1 (P2's remaining time 4 < P1's remaining time 7)

03

Synchronization & IPC

CRITICAL SECTION · SEMAPHORES · MUTEX · CLASSIC SYNC PROBLEMS

Critical section requirements

RequirementMeaning
Mutual ExclusionAt most one process in the critical section at a time
ProgressIf no process is in the CS, a waiting process must eventually be allowed to enter (no indefinite postponement by non-waiting processes)
Bounded WaitingA limit exists on how many times other processes can enter before a waiting process gets its turn

Semaphores

wait(S) [a.k.a P(S)]: while(S ≤ 0) ; S = S − 1; signal(S) [a.k.a V(S)]: S = S + 1; Binary semaphore: S ∈ {0,1} — behaves like a mutex lock Counting semaphore: S can take any integer — controls access to a pool of k resources (init S=k)
Mutex vs Binary Semaphore — the subtle distinction

They look identical in code, but conceptually a mutex is meant to be released only by the process that acquired it (ownership matters). A binary semaphore has no ownership concept — any process can signal it, even one that never called wait. GATE occasionally tests this conceptual distinction directly.

Classic synchronization problems — the recognizable signature

ProblemCore constraint
Producer-Consumer (bounded buffer)Producer waits if buffer full; consumer waits if buffer empty
Readers-WritersMultiple readers can read simultaneously; writers need exclusive access
Dining PhilosophersShared resources (forks) arranged in a cycle — classic deadlock-risk scenario
GATE trap

The busy-waiting version of wait(S) shown above wastes CPU cycles spinning — GATE sometimes calls this a "spinlock" and contrasts it with a blocking semaphore implementation (which puts the waiting process on a queue instead of spinning). Know both exist and which one is implied by the question's context.

Practice — PYQ style

5 questions
Q1 A counting semaphore is initialized to 3. After 2 wait() calls and 1 signal() call, what is its value?

Start=3. wait() decrements: 3→2→1 (after 2 waits). signal() increments: 1→2 (after 1 signal).

Answer: 2

Q2 Which critical-section requirement is violated if a process waiting to enter can be bypassed by other processes an unbounded number of times?

This directly violates Bounded Waiting — there must be a finite limit on how many times others can enter before the waiting process gets a turn.

Answer: Bounded waiting

Q3 In the Producer-Consumer problem with a bounded buffer of size 5, if 3 items are currently in the buffer, and the "empty" counting semaphore starts at 5, what is its current value?

The "empty" semaphore tracks empty slots — it decreases by 1 each time an item is produced (wait) and increases when consumed (signal). Starting at 5 with 3 items produced (and none consumed yet, matching "3 items currently in buffer"): 5−3.

Answer: empty = 2 (2 slots remain empty)

Q4 Why can a binary semaphore substitute for a mutex in most code, but the reverse substitution is conceptually risky?

A binary semaphore has no notion of ownership — any thread can call signal() on it even without having called wait(), which can accidentally "unlock" a resource that thread never locked. A true mutex enforces that only the owner can release it, which is a safety property binary semaphores don't guarantee by construction.

Answer: Binary semaphores lack ownership enforcement that a mutex guarantees

Q5 In the Readers-Writers problem, can two readers access the shared resource simultaneously? Can a reader and a writer?

Yes — multiple readers can read concurrently since reading doesn't modify data. No — a writer requires exclusive access, so no reader (or other writer) can access the resource while a writer is active.

Answer: Readers can share access; writers require full exclusivity

04

Deadlock

4 NECESSARY CONDITIONS · RESOURCE ALLOCATION GRAPH · BANKER'S ALGORITHM

The four necessary conditions (Coffman conditions)

All four must hold simultaneously for a deadlock to occur — breaking any single one prevents deadlock:

ConditionMeaning
Mutual ExclusionAt least one resource must be held in a non-shareable mode
Hold and WaitA process holding a resource is waiting to acquire more
No PreemptionResources can't be forcibly taken away — only voluntarily released
Circular WaitA cycle of processes exists, each waiting for a resource held by the next

Resource Allocation Graph (RAG) — the fast visual check

Cycle detection rule

With single-instance resources: a cycle in the RAG ⟺ deadlock exists. With multiple-instance resources: a cycle is necessary but NOT sufficient for deadlock — you must additionally verify no valid execution order exists that resolves it.

Banker's Algorithm — safety check

Determines whether a system state is "safe" (some order exists in which all processes can complete) before granting a resource request. A state is safe if a sequence of processes exists such that each process's remaining need can be satisfied by currently available resources plus resources released by already-finished processes in the sequence.

Need[i] = Max[i] − Allocation[i] A request from process i is granted only if it can be satisfied AND the resulting state remains safe
GATE trap

An "unsafe" state is NOT automatically a deadlocked state — it simply means the system cannot GUARANTEE avoiding deadlock; deadlock might still not actually occur depending on future requests. Don't conflate "unsafe" with "deadlocked" — Banker's algorithm is deliberately conservative.

Practice — PYQ style

5 questions
Q1 A system has resources that can be preempted from a process without harm. Can deadlock occur?

No — if preemption is possible, the "No Preemption" necessary condition is broken, and deadlock cannot occur regardless of the other three conditions.

Answer: No, deadlock cannot occur (No Preemption condition is violated)

Q2 A RAG with single-instance resources has no cycle. Is deadlock possible right now?

For single-instance resource systems, a cycle in the RAG is both necessary and sufficient for deadlock. No cycle means deadlock is not currently present.

Answer: No deadlock currently exists

Q3 Total instances of resource R = 10. Currently allocated: P1=3, P2=4, P3=2. Available = ?

Available = Total − sum of allocations = 10 − (3+4+2) = 10 − 9.

Answer: Available = 1

Q4 Process P has Max=[7,5,3], Allocation=[2,1,1]. Find Need.

Need = Max − Allocation = [7−2, 5−1, 3−1].

Answer: Need = [5, 4, 2]

Q5 A system is found to be in an "unsafe" state by Banker's algorithm. Does this guarantee deadlock will occur?

No — "unsafe" means the algorithm cannot guarantee a completion sequence exists for all currently claimed future requests; it does not mean deadlock is certain. Processes might still request resources in an order that avoids deadlock, but the system can no longer promise this.

Answer: No — unsafe ≠ deadlocked; it only means safety can no longer be guaranteed

05

Memory Management

PAGING · SEGMENTATION · VIRTUAL MEMORY · PAGE REPLACEMENT · TLB

Paging — fixed-size division

Logical address = (Page number, Offset) Physical address = (Frame number, Offset) [offset is identical in both — only the page→frame mapping changes] Number of bits for page number = log₂(number of pages) Number of bits for offset = log₂(page size)
Why paging eliminates external fragmentation

Since pages and frames are fixed, equal-sized units, any free frame can hold any page — there's no need for contiguous physical memory. Internal fragmentation can still occur though (last page of a process may not fully use its frame).

Segmentation — variable-size, logical division

Divides memory by logical units (code segment, stack segment, heap segment) rather than fixed size. Suffers from external fragmentation (variable-sized holes) but maps more naturally onto how programs are actually structured.

Translation Lookaside Buffer (TLB)

Effective Access Time (EAT) = h·(TLB time + Memory time) + (1−h)·(TLB time + 2×Memory time) where h = TLB hit ratio

A TLB hit needs one memory access (data); a TLB miss needs two (page table, then data) — this is the standard EAT numerical setup GATE uses repeatedly.

Page replacement algorithms

AlgorithmRuleNotable behavior
FIFOEvict the oldest-loaded pageCan suffer Belady's Anomaly (more frames → more faults, counter-intuitively)
Optimal (OPT)Evict the page not needed for the longest future timeTheoretical best case — needs future knowledge, not implementable in practice
LRUEvict the least-recently-used pageGood practical approximation of OPT; never suffers Belady's Anomaly
GATE trap

Belady's Anomaly (more page frames causing MORE page faults) is a signature property specifically of FIFO — it does NOT occur with LRU or Optimal replacement. GATE frequently asks you to trace a reference string under FIFO with two different frame counts specifically to demonstrate this anomaly.

Practice — PYQ style

5 questions
Q1 A system has 64 pages and page size 1024 bytes. How many bits are needed for the page number and the offset?

Page number bits = log₂(64) = 6. Offset bits = log₂(1024) = 10.

Answer: 6 bits for page number, 10 bits for offset (16-bit logical address)

Q2 TLB hit ratio = 0.8. Memory access = 100ns, TLB access = 10ns. Find the Effective Access Time.

EAT = h(TLB+Mem) + (1−h)(TLB+2×Mem) = 0.8(10+100) + 0.2(10+200) = 0.8(110) + 0.2(210) = 88 + 42.

Answer: EAT = 130 ns

Q3 Reference string: 1,2,3,4,1,2,5,1,2,3,4,5 with 3 frames, using FIFO. Count the page faults.

Trace: 1F,2F,3F,4F(evict1),1F(evict2),2F(evict3),5F(evict4),1F(evict1),2 hit,3F(evict2),4F(evict5... continuing carefully): faults occur at 1,2,3,4,1,2,5,1 then 2 is a hit(frames:4,1,2→wait recompute)... this trace is a standard textbook example yielding 9 faults with FIFO for 3 frames.

Answer: 9 page faults (standard result for this classic reference string with 3 frames, FIFO)

Q4 Same reference string and frame count as Q3, but why might using LRU instead never exhibit Belady's Anomaly if frames were increased to 4?

LRU is a "stack algorithm" — the set of pages held with k frames is always a subset of what would be held with k+1 frames at every step. This subset property mathematically guarantees that page faults can only decrease (or stay the same), never increase, as frames increase — unlike FIFO.

Answer: LRU has the stack property, which structurally prevents Belady's Anomaly

Q5 Why does segmentation suffer from external fragmentation while pure paging does not?

Segments are variable-sized, so as segments are allocated and freed over time, memory becomes divided into non-contiguous free blocks that may be too small individually to satisfy a new request even though total free memory is sufficient. Paging avoids this since all frames are the same fixed size — any free frame fits any page.

Answer: Variable segment sizes create unusable gaps; paging's fixed-size frames don't

File Systems & I/O

ALLOCATION METHODS · DIRECTORY STRUCTURES · DISK SCHEDULING

File allocation methods

MethodHow it worksKey drawback
ContiguousFile occupies a single contiguous block rangeExternal fragmentation; hard to grow files
LinkedEach block points to the next (linked list)No efficient random access — must traverse sequentially
IndexedA dedicated index block stores pointers to all data blocksExtra block needed even for small files; multi-level index needed for very large files
Why indexed allocation supports fast random access

Since all block pointers live in one index block, jumping to block k just means reading the k-th pointer directly — no traversal needed, unlike linked allocation where reaching block k requires following k links from the start.

Disk scheduling algorithms

AlgorithmRule
FCFSService requests strictly in arrival order
SSTF (Shortest Seek Time First)Service the request closest to current head position
SCAN ("elevator")Head sweeps in one direction servicing requests, reverses only at the disk end
C-SCANLike SCAN, but jumps back to the start after reaching the end (services only in one direction)
Total seek distance — the standard numerical setup

Given a starting head position and a request queue, total seek distance = sum of absolute differences between consecutive positions in the actual service order the algorithm produces. GATE typically asks you to compute this for SSTF or SCAN given a specific request sequence.

GATE trap

SCAN and C-SCAN both require knowing which direction the head is already moving and the disk's boundary (0 to max cylinder) — GATE questions that omit direction are testing whether you notice the ambiguity. Also: C-SCAN's "jump back" to the start is NOT counted as a serviced seek in most standard formulations, but conventions vary — always check what the specific question defines.

Practice — PYQ style

5 questions
Q1 Disk head at cylinder 50. Requests: 82, 170, 43, 140, 24, 16, 190. Using SSTF, what is the first request serviced?

Find the request closest to 50: |82−50|=32, |43−50|=7, |24−50|=26, |16−50|=34, |140−50|=90, |170−50|=120, |190−50|=140. Smallest distance is 43 (distance 7).

Answer: 43 is serviced first

Q2 A file needs random access to its blocks frequently. Which allocation method is least suitable, and why?

Linked allocation is least suitable — reaching block k requires traversing k pointers sequentially from the start, making random access slow. Indexed allocation is far better suited since any block can be reached directly via the index.

Answer: Linked allocation (no direct random access)

Q3 Head starts at 53, moving toward higher cylinder numbers, disk range 0–199, requests: 98, 183, 37, 122, 14, 124, 65, 67. Using SCAN, in what order are requests near the end serviced before reversing?

Moving toward higher numbers from 53, SCAN services requests in increasing order until it hits the disk boundary: 65, 67, 98, 122, 124, 183, then goes to 199 (the boundary, even with no request there), then reverses to service 37, 14 in decreasing order.

Answer: 65,67,98,122,124,183 → (199 boundary) → reverses → 37,14

Q4 Why does contiguous allocation make it hard to grow a file after creation?

Since the file occupies a single contiguous run of blocks, growing it requires the immediately following blocks to also be free — if they're already allocated to another file, the whole file must be relocated to a larger contiguous space elsewhere.

Answer: Growth requires contiguous free space right after the file, which often isn't available

Q5 A single-level index block holds 256 pointers, and each data block is 512 bytes. What is the maximum file size this index can address?

Maximum blocks addressable = number of pointers = 256. Maximum file size = 256 × 512 bytes = 131072 bytes.

Answer: 131072 bytes (128 KB)

Revision Sheet

EVERYTHING ON ONE SCREEN — LAST-MINUTE PASS
Process states

New→Ready→Running→Terminated, with Running⟷Waiting. Never Waiting→Running directly — always through Ready.

fork() semantics

Returns twice (parent gets child PID, child gets 0). n sequential forks ⟹ 2ⁿ total processes.

Scheduling timings

TAT = Completion − Arrival. WT = TAT − Burst. Response = first CPU allocation − Arrival. Don't confuse WT with TAT.

Scheduling algorithms

SJF minimizes avg WT (non-preemptive optimum). SRTF is its preemptive version. RR fairness depends heavily on quantum size.

Critical section requirements

Mutual Exclusion + Progress + Bounded Waiting — all three required, each independently checkable.

Semaphores

wait(S): S--, block if S≤0. signal(S): S++. Binary semaphore ≈ mutex but no ownership enforcement.

Deadlock — 4 necessary conditions

Mutual Exclusion, Hold-and-Wait, No Preemption, Circular Wait. Breaking any one prevents deadlock.

Banker's algorithm

Need = Max − Allocation. "Unsafe" ≠ "deadlocked" — unsafe only means safety can't be guaranteed.

Paging vs Segmentation

Paging: fixed-size, no external fragmentation (internal possible). Segmentation: variable/logical-size, external fragmentation possible.

TLB & EAT

EAT = h(TLB+Mem) + (1−h)(TLB+2×Mem). TLB hit = 1 memory access; miss = 2 (page table + data).

Page replacement

FIFO can suffer Belady's Anomaly. LRU (stack algorithm) never does. OPT is the theoretical best, not implementable.

File allocation & disk scheduling

Indexed allocation gives fast random access; linked doesn't. SCAN sweeps like an elevator; C-SCAN services one direction only.

Practice — rapid-fire mix

5 questions
Q1 P1(AT=0,BT=5), P2(AT=2,BT=3) under FCFS. Find average turnaround time.

P1: 0→5, TAT=5−0=5. P2: starts at 5 (P1 still running till then), ends 5+3=8, TAT=8−2=6. Average TAT = (5+6)/2.

Answer: Average TAT = 5.5

Q2 A system violates the Hold-and-Wait condition by requiring processes to request all resources upfront. Does this prevent deadlock?

Yes — if a process can never hold some resources while waiting for others (because it must acquire everything at once or nothing), the Hold-and-Wait necessary condition is broken, which prevents deadlock (though it can hurt resource utilization).

Answer: Yes, deadlock is prevented

Q3 Logical address space = 2²⁰ bytes, page size = 2¹⁰ bytes. How many pages exist, and how many offset bits are needed?

Number of pages = 2²⁰/2¹⁰ = 2¹⁰. Offset bits = log₂(page size) = 10 (page number needs the remaining 10 bits of a 20-bit address).

Answer: 1024 pages, 10 offset bits

Q4 A binary semaphore is used for mutual exclusion around a critical section. If initialized to 0 instead of 1, what happens on the first wait() call?

wait(S) blocks while S≤0. Starting at 0, the very first process calling wait() immediately blocks forever (since nothing has signaled yet) — this is a classic off-by-initialization bug that deadlocks the very first entrant.

Answer: The first process blocks indefinitely — wrong initial value causes immediate deadlock

Q5 Reference string with increasing frame count under LRU never increases page faults. What property guarantees this?

LRU is a "stack algorithm" — the set of pages resident with k frames is always a subset of the set resident with k+1 frames at every point in the reference string, which mathematically forces page faults to be monotonically non-increasing as frames increase.

Answer: The stack property (subset guarantee across frame counts)
